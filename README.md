# Abramov Shop

Интернет-магазин **abramov.shop**: личный кабинет с бонусами, анимированный логотип, вход по почте и через Google, журнал согласий на обработку персональных данных, блокировка клиентов с окном причины и админка.

Next.js 16 · React 19 · TypeScript · PostgreSQL · Drizzle ORM · Better Auth. Дизайн «Sport Pro»: графит, золото и серебро из логотипа, шрифты Oswald и Montserrat лежат в проекте.

## Что уже работает

| Раздел | Что внутри |
|---|---|
| Главная | Анимированное лого (золотая «А» прорисовывается и заливается, серебряная полоса въезжает, буквы появляются по одной, по золоту пробегает блик), категории, лимитка Kamui с живым остатком, уровни Silver / Gold / Black, блок поддержки, реквизиты ИП в подвале |
| Регистрация | Почта + пароль или «Продолжить с Google». **Без галочки согласия аккаунт не создаётся** — это проверяет сервер, а не только кнопка |
| Журнал согласий | Каждая галочка: имя, телефон, почта, IP, браузер, время, где отмечено, какая редакция текста (с хешем SHA-256). Записи не удаляются, отзыв — отдельной отметкой. Выгрузка в Excel |
| Личный кабинет | Бонусная карта с уровнем и прогрессом, реферальный код, заказы, переключатели «Telegram-уведомления» и «Новости и акции» (включение и выключение пишутся в журнал) |
| Блокировка | В админке: причина, срок (день / неделя / месяц / до даты / навсегда). Клиент при входе видит окно с причиной, сроком, номером обращения и кнопкой в Telegram поддержки. Истёкший бан снимается сам |
| Скрытие | У страниц, категорий и товаров статус: черновик / скрыто / опубликовано + публикация по расписанию. Скрытое не видно покупателям, в подвале и в sitemap.xml; админ открывает его по ссылке «Предпросмотр» |
| Админка `/admin` | Клиенты (поиск, бан, бонусы, роли), журнал согласий, страницы (редактор текста), каталог (видимость), настройки (техработы, Telegram поддержки, проценты и пороги бонусов), журнал действий админов |
| Режим техработ | Одна галочка в настройках: покупатели видят заглушку, админы — сайт |

## Следующие этапы

1. Товары в админке: фото, варианты, остатки.
2. Корзина и оформление заказа, промокоды, списание бонусов.
3. Оплата ЮKassa (чеки 54-ФЗ) и доставка СДЭК: виджет ПВЗ, расчёт цены, накладная одной кнопкой, трек в кабинете.
4. Начисление бонусов после получения заказа, реферальные и именинные бонусы, сгорание.
5. Telegram-бот: статусы заказов клиентам, новые заказы админам.
6. Подтверждение почты и восстановление пароля.

## Запуск на своём компьютере

Нужен Node.js 20.9 или новее.

```bash
npm install
cp .env.example .env.local      # заполните настройки
npm run db:local                # в отдельном окне: локальная база без установки PostgreSQL
npm run db:migrate              # создать таблицы
npm run db:seed                 # тексты согласий, страницы, категории, товар Kamui, настройки
npm run dev                     # http://localhost:3000
```

Для `db:local` в `.env.local` укажите `DATABASE_URL=postgresql://postgres@127.0.0.1:5433/postgres`.

**Как стать админом:** зарегистрируйтесь на сайте с почтой из `OWNER_EMAIL` и ещё раз выполните `npm run db:seed` — аккаунт получит права владельца. Дальше роли выдаются в админке → «Клиенты».

## Выкладка на Timeweb Cloud

1. **База.** «Облачные базы данных» → PostgreSQL. Скопируйте строку подключения в `DATABASE_URL`.
2. **Приложение.** «Apps» → Frontend/Backend → Next.js, подключите репозиторий `abramov.shop` (ветка `main`).
   - Команда сборки: `npm ci && npm run build`
   - Команда запуска: `npm run db:migrate && npm start`
3. **Переменные окружения** — все из `.env.example`. `BETTER_AUTH_SECRET` сгенерируйте: `openssl rand -base64 32`.
4. **Домен** abramov.shop → в настройках приложения, SSL выпустится автоматически.
5. Один раз после первого деплоя: `npm run db:seed` (в консоли приложения).

### Вход через Google

1. [console.cloud.google.com](https://console.cloud.google.com) → создайте проект → «APIs & Services» → «OAuth consent screen»: название Abramov Shop, почта поддержки, домен abramov.shop.
2. «Credentials» → «Create credentials» → «OAuth client ID» → Web application.
3. Authorized redirect URI: `https://abramov.shop/api/auth/callback/google`
4. Client ID и Client secret → в `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`. Пока они пустые, кнопка Google на сайте не показывается.

## Как устроена галочка согласия

1. Человек отмечает галочку и нажимает «Зарегистрироваться» или «Продолжить с Google».
2. Сайт сначала отправляет отметку на `/api/consent`: она сразу записывается в журнал (IP, браузер, время, редакция текста), а браузер получает cookie с токеном на 30 минут.
3. При создании аккаунта сервер входа ищет по токену свежую отметку. Нет отметки — аккаунт не создаётся (даже если кто-то обойдёт форму).
4. После создания аккаунта отметки привязываются к нему, телефон из формы попадает в профиль.
5. Если у аккаунта нет действующего согласия (например, его отозвали), кабинет отправляет на страницу повторного согласия.

Тексты согласий хранятся редакциями в таблице `consent_document`. Новая редакция = новая строка с `is_current = true`; старые записи журнала остаются привязаны к той редакции, которую человек видел. Перед запуском покажите тексты в `src/content/legal.ts` юристу.
